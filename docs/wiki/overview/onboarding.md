The rules below come from the repository's `AGENTS.md` files: the root one, which holds what applies to every change, and nested ones loaded when you work inside a subtree (`src/drawmaha_solver/`, `src/drawmaha_solver/minidrawmaha/`, `src/drawmaha_solver/deepcfr/`, `tests/`, `scripts/`, `web/`, `docs/`). Each rule exists because breaking it fails silently: the code still runs and still produces a confident number.

## The rules that hold everywhere

### A grader never shares code with what it grades

Every rung's `exploitability.py` imports the game rules and nothing from the solver. A bug shared between the two would appear in both and cancel, and the meter would certify the thing that broke it. A review of a grader starts with its import block.

Inside a grader, the order of operations is fixed: **sum over the hidden worlds first, then take the responder's max**. A max inside the sum is an adversary who sees face-down cards. At Kuhn, a test pins that a peeking meter scores a genuine Nash equilibrium at 0.278 chips/hand. At mini-drawmaha, grouping the responder's max by the table's key instead of by physical state under-reports by about 0.012 chips/hand (`src/drawmaha_solver/minidrawmaha/AGENTS.md`). See [Exploitability](wiki:theory/exploitability).

### CFR's two reach weights are keyword-only

`RegretMatcher.update(utilities, *, regret_weight, strategy_weight)` in `src/drawmaha_solver/regret_matching.py`. Regret is weighted by the counterfactual reach π₋ᵢ (chance and the opponent), the average by the player's own reach πᵢ. Swapped, every rung still converges — to a wrong answer, with no warning. At Kuhn the swapped run folds the king to a bet 18% of the time. Never make them positional. See [CFR](wiki:theory/cfr).

### Committed fixtures, figures and exports are regenerated, never hand-edited

`tests/leduc/referee.json`, `tests/minidrawmaha/census.json`, everything under `figures/`, the packs under `web/rung3-viz/public/deals/` and `web/solver-viz/public/mini/`, and the copies under `web/*/src/data/`. Each names the command that writes it. The tests re-derive the numbers in them a second way, so a fixture that merely asserted itself would pass while the solver rotted. The static pages, this wiki included, are regenerated by `scripts/site/make_static_pages.py`.

### CI runs no tests

The only GitHub workflow is an automated review. `uv run pytest` is the gate, and you run it yourself before every PR, plus `npm test` in any app you touched. The default suite must pass without torch, Modal, OpenSpiel or a network download.

### Docstrings and the README are the design record

The reviewer re-derives the math a docstring states. A wrong claim in a docstring or in `README.md` is a bug, fixed in the same change as the code. Convergence numbers quoted in either are recomputed by a test from committed data, never transcribed from a session.

### PRs branch from their predecessor's head and target `main`

Never stack a PR on another's branch, and never rebase a branch onto `main` to clean its diff: that deletes the modules it imports. Commit subjects state the finding:

- `feat(rung4): <the finding>`
- `fix(web): <the finding>`

### Modal costs money

The launchers under `scripts/` that run on Modal are started by a person, never by an agent on its own initiative. Deploy first (free), then run. See [Modal](wiki:ops/modal).

### Never `git stash`

Several agents work in parallel worktrees that share one stash stack; a bare `git stash pop` can take another session's changes.

## Code rules: column order, seeding, optional torch, the oracle pin

| Where | Rule | Why |
| --- | --- | --- |
| Every rung | Loops over a ledger's columns pair `enumerate(legal_actions())` with the ledger | column 0 means *call* at the open and *fold* facing a raise; nothing else keeps them in step |
| Rungs 1–2 | Run unseeded | vanilla CFR enumerates the whole tree, so two runs agree bit for bit and `figures/` is a fingerprint |
| Rungs 3–4 | Every sampled quantity is a function of (seed, iteration, seat, walk index), never of the worker count | parallel must equal serial bit for bit; a run resumes exactly |
| Mini-drawmaha | Do not simplify DCFR's deferred discount or CFR+'s per-bank floor to the textbook form | a row can be banked twice in one traversal through the suit relabelling |
| Deep CFR | torch stays optional; torch tests `importorskip` it | the default suite runs on `uv sync` alone |
| Deep CFR | The oracle pin is the correctness gate: with `OracleLearner` the loop reproduces rung 3's LCFR table bit for bit | if it breaks, the loop is wrong, not the test |
| Deep CFR | A field added to `DeepConfig` after runs were saved goes in `ADDED_LATER` with the old value | a saved run must resume as the run it was |
| Tests | `--import-mode=importlib`; test modules never import one another | every rung has its own `test_game.py` |
| Tests | Slow work is gated by `MINIDRAWMAHA_FULL_TABLE`, `MINIDRAWMAHA_FULL_GRADE`, `MINIDRAWMAHA_FULL_CALIBRATION`, `MINIDRAWMAHA_FULL_DEEP` | the default suite stays fast |
| Tests | Loosening a convergence threshold to pass is a finding to report, not a fix | thresholds are seeded and justified in a comment |
| Web | No CFR in TypeScript | one implementation of the walk, in Python |
| Web | Five chrome files are byte-identical across the five apps | `tests/test_shared_chrome.py` holds it |

## Adding a surface to the site

From `web/AGENTS.md`. A new app or static page touches:

1. `vercel.json` — a rewrite for its route.
2. `scripts/site/vercel_build.sh` — the `rungs` list for an app, or the page loop for a static page.
3. `tests/test_shared_chrome.py` and `tests/test_ui_standard.py` — the `APPS` tuple for an app; for a page, `PAGES` there and in `tests/test_cover_page.py`.
4. If the nav names it: `NAV` and the `Surface` type in `site.tsx` (copied to all five apps), and `NAV` in `scripts/site/make_static_pages.py`; then regenerate the pages.

Read `web/DESIGN.md` before touching any stylesheet, and afterwards run:

```bash
uv run pytest tests/test_ui_standard.py tests/test_shared_chrome.py tests/test_cover_page.py
```

## Before you open a PR

1. `uv run pytest` passes, and `npm test` in every app you touched.
2. Any figure, export or static page your change affects is regenerated and committed.
3. Docstrings and `README.md` say what the code now does.
4. If you added a path to an `AGENTS.md`, it exists: `tests/test_agent_docs.py` checks every backticked path and every `CLAUDE.md` shim.
5. The commit subject states the finding.
