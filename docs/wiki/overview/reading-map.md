The repository keeps three kinds of writing, and knowing which is which saves reading the wrong one. **Living documents** are corrected in place when the code or a run changes them. **Dated records** say why the code looks the way it does on the day they were written and are never rewritten. **Instructions** tell an agent or a contributor what to do in a subtree.

## Which file to read

| When you want to… | Read |
| --- | --- |
| Understand the whole project, rung by rung | `README.md`, the long-form narrative, kept current |
| Know the rules for any change | the root `AGENTS.md`, then the nested `AGENTS.md` of the subtree you are in — summarised in [Onboarding](wiki:overview/onboarding) |
| Touch a stylesheet or a component's classes | `web/DESIGN.md`, the enforced UI standard |
| Edit the homepage, Rules, Benchmarks, Releases or this wiki | `web/cover/README.md` and `docs/wiki/README.md`; the pages are generated by `scripts/site/make_static_pages.py` |
| Continue rung 4 (Deep CFR) | `docs/superpowers/specs/2026-10-07-deep-cfr-m1-design.md`, the PR ladder and its gates |
| Plan a rung 4 run, or try a regret rule other than linear | `docs/notes/rung4-run-log.md` (every arm and its grades) and `docs/notes/regret-rules-dcfr-cfrplus.md` (why DCFR and CFR+ lost twice) |
| Know why a design decision was made | `docs/superpowers/specs/` for designs, `docs/superpowers/plans/` for the dated plan each PR was built from |
| Change mini-drawmaha's deck, draw cap, betting tree or infoset key | the rung 3 plan, which lives outside the repo on Alec's machine (`~/Desktop/Claude/poker/rung3-delta/rung3-delta-plan.md`, §3 rules, §4 census) |
| Read the literature the solver draws on | the ML survey in `paper/` (`paper/drawmaha-ml-survey.pdf`) and the nine notes in `docs/research/` — see [Literature](wiki:research/literature) |
| See how `/solver`'s panes were placed | `docs/research/range-ui-studies/` |
| Read a code walkthrough of a merged PR | `docs/notes/walkthrough-pr61-mps-refit.md`, `docs/notes/walkthrough-pr62-regret-rule-screen.md` |
| Know what a committed figure is and which command writes it | `figures/AGENTS.md` and the rung's section of `README.md` |
| Run something on Modal | the launcher's docstring under `scripts/`, and [Modal](wiki:ops/modal); it costs money |

## Living vs dated documents

| Kind | Where | Rule |
| --- | --- | --- |
| Living | `README.md`, `docs/notes/`, docstrings, this wiki | Correct a wrong claim in place, in the same change as the code. Every number in `docs/notes/` is read from a committed file under `figures/`, and the file wins when they disagree. |
| Dated record | `docs/superpowers/specs/`, `docs/superpowers/plans/` | Never rewritten to match what shipped. A change of direction gets a new document; the old one stays as the reason. |
| Finished reference | `docs/research/`, `docs/writeups/rung0-rps/`, `paper/` | Not updated as the code moves. |
| Instructions | every `AGENTS.md` (with its one-line `CLAUDE.md` shim) | `tests/test_agent_docs.py` checks every backticked path exists. |

:::note
Paths in documents dated before 2026-10-20 predate two moves: `scripts/` was grouped into `scripts/site/`, `scripts/leduc/`, `scripts/minidrawmaha/` and `scripts/deepcfr/`, and `minidrawmaha/` was grouped into `rules/`, `solver/` and `answer/`. Documents before 2026-10-28 also predate the move of the top-level `research/` and `writeups/` into `docs/`. Read an older path with that mapping in mind rather than treating it as missing (`docs/AGENTS.md`).
:::

## Where this wiki sits

The wiki explains; it is not a second source of results. Its numbers are quoted from the README and from `figures/`, and it names where each comes from. When the two disagree, the committed file is right and the wiki is the bug.
