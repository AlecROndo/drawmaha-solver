The project is one Python package that solves games, one directory of committed outputs, and one website that draws those outputs. Data flows in one direction: Python computes, writes a file into the repository, and every downstream surface reads that file. Nothing on the site re-implements the solver, and nothing in a grader imports it.

## Data flows one way: solve, grade, export, draw

1. **Rules** — each game's `game.py` (for mini-drawmaha, the `rules/` subpackage) defines the state machine, the infosets and the payoffs, with no solver in it.
2. **Solver** — CFR (`cfr.py`, rungs 1–2), sampled lockstep MCCFR (`minidrawmaha/solver/`, rung 3) or Deep CFR (`deepcfr/`, rung 4) trains the regret ledgers and accumulates the average strategy.
3. **Grader** — each rung's `exploitability.py` imports the rules alone and computes the exact best response against the solver's average.
4. **Analysis and export** — entry points registered in `pyproject.toml` (`kuhn-analysis`, `minidraw-analysis`, `deep-analysis`, `minidraw-deals`, `minidraw-ranges`, …) write figures to `figures/<rung>/` and JSON exports to the apps' `public/` folders.
5. **Site** — five Vite + React apps and five static pages read those files. The static pages are written by `scripts/site/make_static_pages.py` from the same committed numbers; Vercel builds and serves everything.

Heavy runs (the rung 3 race and the rung 4 arms) train on Modal or on a Mac, write checkpoints to Modal volumes or a local directory, and come back into the repository only as graded JSON under `figures/` and as release assets on GitHub.

:::note
The layering inside a rung is always the same: the rules → the ledgers (`infoset_table.py`) → the solver → the meter (`exploitability.py`) → the entry points (`analysis.py`, `play.py`, `exploit_server.py`). Reading any rung in that order works (`src/drawmaha_solver/AGENTS.md`).
:::

## Components

| Component | Where | Technology | Role |
| --- | --- | --- | --- |
| **Shared ledger** | `src/drawmaha_solver/regret_matching.py` | Python + NumPy | Regret matching: the one learning rule every rung trains. |
| **Graded games** | `src/drawmaha_solver/{rps,kuhn,leduc}/` | Python | The three toys, each with rules, solver, exact grader, analysis, terminal play; Kuhn and Leduc also an exploit server. |
| **Mini-drawmaha** | `src/drawmaha_solver/minidrawmaha/` | Python + NumPy, multiprocessing | `rules/` (the game, 6,220,050 infosets), `solver/` (lockstep MCCFR, packed table, regret rules), `answer/` (frozen strategy, analysis, exports, release catalogue), and `exploitability.py`. |
| **Deep CFR** | `src/drawmaha_solver/deepcfr/` | Python + torch (optional `deep` extra) | Nets, reservoirs, the collector, the train loop, the exact running average and the policy net. |
| **Referee** | `scripts/leduc/generate_referee.py` | OpenSpiel (never a dependency) | Writes `tests/leduc/referee.json` once, by hand. |
| **Training launchers** | `scripts/minidrawmaha/modal_rung3.py`, `scripts/deepcfr/modal_rung4.py`, `scripts/deepcfr/run_deep_cfr.py` | Modal, or local | The rung 3 race and the rung 4 runs. Started by a person, never by an agent. |
| **Committed outputs** | `figures/` | PNG + JSON | Every analysis command's output, committed as a regression fingerprint. |
| **Static pages** | `web/cover/` | HTML generated by `scripts/site/make_static_pages.py` | Homepage, Rules, Benchmarks, Releases, Wiki; the archived Cover. |
| **Apps** | `web/rung0-viz`, `rung1-viz`, `rung2-viz`, `rung3-viz`, `solver-viz` | Vite + React + TypeScript | The three benchmark demos, the research publication with Learn and Play tabs, the range explorer. |
| **Deploy** | `vercel.json`, `scripts/site/vercel_build.sh` | Vercel | Builds the apps into `public/`, copies the static pages, fonts and theme. |
| **Tests** | `tests/` | pytest; vitest per app | The suite is the CI: no workflow runs tests. |

## What the site reads, and from where

| Surface | Route | Reads |
| --- | --- | --- |
| Homepage, Benchmarks, Releases | `/`, `/benchmarks`, `/releases` | the README's results tables, `figures/rung3/` and `figures/rung4/` grades, `answer/releases.py` — baked in at generation time |
| Research, Learn, Play | `/research`, `/learn`, `/play` | `web/rung3-viz`; the Play tab's deal pack under `web/rung3-viz/public/deals/` (written by `minidraw-deals`) |
| Range explorer | `/solver` | per-decision-point exports under `web/solver-viz/public/mini*/` (written by `minidraw-ranges`) |
| Kuhn and Leduc demos | `/rung1`, `/rung2` | the solves exported by `kuhn-analysis --json` and `leduc-analysis --json`; the Exploit tabs POST to a local exploit server |
| Rock-paper-scissors demo | `/rung0` | runs the 63-line ledger in the browser, the one place a learner is ported |

:::warning
The browser never re-implements CFR. A second copy of the reach-weighted walk would be a second place for a swapped weight to converge silently to the wrong answer. Only rules arithmetic is transcribed to TypeScript, and each app's tests pin it against the same tables the Python suite pins (`web/AGENTS.md`).
:::
