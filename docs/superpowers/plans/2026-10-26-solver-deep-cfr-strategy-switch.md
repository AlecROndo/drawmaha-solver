# `/solver` shows Deep CFR too: three exports behind one switch — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The mini-drawmaha view of `/solver` (PR #54) shows the tabular LCFR strategy *or* one of rung 4's two Deep CFR strategies at iteration 500 — Π, the policy net, and the exact running average — chosen by a switch on the page that keeps the spot, the held cards and the filters, with a status line that names the strategy showing and quotes its graded exploitability from the committed grades file.

**Architecture:** One exporter, three release assets. `range_export.py` gains a table of the strategies the site ships (`RELEASES`: a GitHub release asset, its SHA-256, and where in `figures/` its grade is recorded); `minidraw-ranges --release NAME` fetches the asset, exports to `web/solver-viz/public/<dir>/`, and writes the grade into `index.json` so the browser reads provenance and grade from the one file it loads. The fixtures depend on the rules alone, so the exporter refuses to overwrite a committed `fixtures.json` that differs. In the browser the strategy is a third hash segment (`#mini/range/deep-pi`), a `Strategies` loader caches one `MiniData` per export, and `MiniRange` swaps the `data` it computes ranges from while every piece of view state stays put.

**Tech Stack:** Python 3.12 + numpy (exporter), Vite + React 19 + TypeScript + vitest (app), `gh` for the release.

**Spec:** the handoff prompt of 2026-10-26 (`.context/attachments/ohyZcn/pasted_text_2026-10-26_02-41-11.txt` in workspace delhi), Alec's decisions in that conversation (ship both Π and exact; the release may be public), and the export contract in `docs/superpowers/plans/2026-10-07-solver-minidrawmaha.md`.

## Global Constraints

- No CFR in TypeScript; the browser only renders Python's exports.
- The five shared chrome files in `web/solver-viz/src` stay byte-identical to rung 0's.
- Every number on the page is the named strategy's; the status line stays true when the switch flips.
- `web/DESIGN.md`: the switch is a pressable (`.seg button` is already in `PRESSABLES["solver-viz"]`), no chrome motion over 300 ms, identity colour only inside figures.
- Exports and figures are regenerated by a command, never hand-edited. No Modal launch. Never `git stash`.
- Release assets: tag `rung4-deep-t500`, files `deep-256x4-s16000-lr5e-4-t500-pi.npz` and `deep-256x4-s16000-lr5e-4-t500-exact.npz`; the tabular one stays `rung3-lcfr-2m` / `strategy-lcfr-2m.npz`.
- Export directories: `public/mini/` (tabular, unchanged chunks), `public/mini-deep-pi/`, `public/mini-deep-exact/`.
- Commit subjects `feat(rung4): <the finding>`; docstrings are the design record.

## Review Focus

1. `--strategy PATH` for a file that is not a release must not silently export to `public/mini/` with no grade: the parser refuses it without `--out` (Task 1 tests it).
2. A re-export after a re-grade must not leave `index.json` quoting a stale number: the committed-export test reads the grade back from the grades file (Task 1).
3. The three exports must enumerate the same states at every spot, or the switch would silently change the filter's meaning: Task 2 checks the key tables are byte-identical and a range at a spot has the same `cards` under all three.
4. A hash with a bad strategy segment (`#mini/range/foo`) must fall back to tabular, never throw (Task 2).
5. Switching while a range is computing must not show one strategy's numbers under another's status line: the status line reads from the same `data` object the ranges were computed from, and a stale result is dropped by the existing `live` guard (Task 3 drives it in headless Chrome).

**Interfaces (produces):**
```python
@dataclass(frozen=True, slots=True)
class Release:
    name: str        # CLI name: "tabular" | "deep-pi" | "deep-exact"
    directory: str   # under web/solver-viz/public/: "mini" | "mini-deep-pi" | "mini-deep-exact"
    tag: str; asset: str; sha256: str
    grade_file: str  # repo-relative JSON
    grade_key: str   # the object in it that holds "exploitability"
    @property
    def url(self) -> str
    @property
    def out(self) -> Path
RELEASES: dict[str, Release]
def release_of(sha256: str) -> Release | None
def read_grade(release: Release, info: StrategyInfo, *, root: Path = REPO) -> Grade   # Grade(exploitability, hands_per_seat, file, key)
def main(argv) -> None   # --release NAME | --strategy PATH [--out DIR] [--fixtures PATH] [--write-fixtures] [--scale N]
```
`index.json` gains `strategy.release` (the tag or `null`), `strategy.asset` (the file name) and a top-level `grade` block `{"exploitability", "handsPerSeat", "file", "key"}` or `null`.
